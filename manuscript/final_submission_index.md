# Final submission index

This index is the human-facing entry point for the manuscript finalization package. Use it after `scripts/finalize_cee_publication_package.py` has completed successfully.

## Primary manuscript files

- `process_terrain_coastal_flood_CEE_manuscript.md` — current manuscript text.
- `process_terrain_coastal_flood_CEE_manuscript_review.html` — standalone review HTML with embedded figures.
- `publication_readiness_report.md` — final command log, artifact manifest and audit evidence generated by the finalization workflow.
- `completion_status.json` — machine-readable finalization status, output paths and manual completion requirements.
- `final_archive_manifest.json` — root-level final archive size and SHA256 record for `publication_package.zip`. It is intentionally not placed inside the ZIP to avoid self-referential archive hashing.

## Acceptance rule

Do not treat the package as final unless:

1. `python scripts\finalize_cee_publication_package.py` exits with code 0.
2. `publication_readiness_report.md` records `PUBLICATION READINESS AUDIT: PASS`.
3. `publication_package.zip` exists and includes `package_manifest.json`.
4. `publication_package/completion_status.json` exists and reports `status: finalized`.
5. `python scripts\validate_publication_package.py` reports `PUBLICATION PACKAGE VALIDATION: PASS`.
6. `logs/final_archive_validation.txt` confirms validation after the final ZIP was written.
7. `final_archive_manifest.json` records the final `publication_package.zip` size and SHA256.
8. The standalone review HTML has been opened and visually checked.
9. Author-governance metadata in `author_final_confirmation_form.md` has been completed.
10. No `publication_package_failed_status.json` is present with `safe_to_use_existing_package: false`.
## Final evidence logs

The final gate must produce `logs\python_runtime_dependencies_audit.txt`, `logs\manuscript_figure_inventory.md`, `logs\figure_deliverables_audit.txt`, `logs\figure_visual_quality_audit.txt`, `logs\manual_figure_review_sheet.md`, `logs\figure_data_integrity_audit.txt`, `logs\manuscript_submission_text_audit.txt`, `logs\reference_metadata_audit.txt`, `logs\journal_submission_metadata_audit.txt`, `logs\submission_artifact_consistency_audit.txt`, `logs\final_qc_acceptance_audit.txt`, `logs\repository_deposit_readiness_audit.txt`, `logs\publication_package_validation.txt`, `logs\final_archive_validation.txt`, `logs\archive_handoff_audit.txt`, `logs\publication_readiness_summary.md`, and `logs\final_evidence_index.md`. These logs are the evidence trail for runtime dependencies, figure presence, figure deliverables, visual quality, manual figure review, source-data integrity, text readiness, reference metadata, journal submission metadata, artifact consistency, final QC acceptance, repository deposit readiness, package validity, archive validity, handoff boundary checks, and final sign-off.
## Evidence bundle hash check

The final gate must produce `publication_gate_evidence\evidence_manifest.json` and `publication_gate_evidence\evidence_manifest.sha256`. The sidecar records the SHA256 hash of the evidence manifest without creating a self-referential JSON hash.
