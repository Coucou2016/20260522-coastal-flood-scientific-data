# Submission package matrix

This matrix maps each expected submission or archive component to the local artifact that should be included in the final package.

| Component | Local artifact | Status rule |
|---|---|---|
| Manuscript text | `manuscript/process_terrain_coastal_flood_CEE_manuscript.md` | Must contain no unresolved submission placeholders and must include the no-fabricated-data statement. |
| Standalone review HTML | `manuscript/process_terrain_coastal_flood_CEE_manuscript_review.html` | Must embed current PNG figures as Base64 and contain no external CSS, scripts or image paths. |
| Main figures | `figures/main/Fig1_*.png/.pdf` to `figures/main/Fig5_*.png/.pdf` | PNG and PDF versions must exist; PNG dimensions must pass publication-readiness audit. |
| Figure source data | `data/figure_source/*.csv` | All declared source CSV files must exist and be non-empty. |
| Terrain sensitivity source | `data/figure_source/Fig4_connected_terrain_sensitivity.csv` | Must use DeltaDTM sources; ocean-connected fractions must not exceed non-connected bathtub fractions. |
| Typology source | `data/figure_source/Fig5_process_terrain_typology.csv` | Must inherit `D10_m`, pressure correlation and connected +2 m sensitivity from upstream source tables. |
| Reproducibility report | `manuscript/publication_readiness_report.md` | Must be generated by a successful finalization run. |
| Compact package directory | `publication_package/` | Must include manuscript, HTML, figures, source data, scripts and audit documents. |
| Portable package archive | `publication_package.zip` | Must contain the compact package and pass archive verification. |
| Software environment | `manuscript/software_environment.md` | Must list the intended runtime and dependency expectations. |
| Source-data dictionary | `manuscript/figure_source_data_dictionary.md` | Must explain the key columns used in figures and tables. |
| Reviewer-risk register | `manuscript/reviewer_risk_register.md` | Must identify interpretation boundaries and reviewer-facing evidence. |
| Claims-evidence matrix | `manuscript/claims_evidence_matrix.md` | Must map every major claim to figures, source data, calculations and interpretation boundaries. |
| Submission metadata | `manuscript/submission_metadata_required.md` | Must list author/funding/repository items requiring author confirmation. |
| Cover letter draft | `manuscript/cover_letter_draft.md` | Must be checked and completed by the corresponding author before use. |
| Editorial significance statement | `manuscript/editorial_significance_statement.md` | Can be adapted for journal submission fields, but should not be used until the final audit passes. |

| Author final confirmation | `manuscript/author_final_confirmation_form.md` | Must be completed by the author group before journal upload. |
| Title page and declarations draft | `manuscript/title_page_and_declarations_draft.md` | Provides a single editable template for title page, data/code availability, funding, competing interests, ethics and AI-use disclosure. |
| Release notes template | `manuscript/publication_release_notes_template.md` | Should be completed for any archived or shared manuscript package release. |
| Target-journal checklist | `manuscript/target_journal_cee_checklist.md` | Should be checked against current Communications Earth & Environment instructions immediately before submission. |
| External finalization guide | `manuscript/external_finalization_guide.md` | Explains how to run the finalization workflow from a normal terminal, another machine, or a fresh environment if the current session runner fails. |
| Nature Reporting Summary preparation | `manuscript/nature_reporting_summary_preparation.md` | Prepares likely Nature Portfolio reporting-summary answers for study design, exclusions, data, code and ethics fields. |
| AI-use statement draft | `manuscript/ai_use_statement_draft.md` | Should be adapted to the target journal's current AI-tool disclosure policy. |
| Data/code availability final draft | `manuscript/data_code_availability_final_draft.md` | Should be updated with repository URLs/DOIs after public archival and then inserted into the manuscript. |
| Data repository deposit checklist | `manuscript/data_repository_deposit_checklist.md` | Guides public archive contents, upstream-data citation, metadata, keywords and license checks. |
| Repository README template | `manuscript/repository_readme_template.md` | Can be adapted as the README for the public archive that hosts processed data, code and package files. |
| Citation metadata template | `manuscript/citation_metadata_template.md` | Provides fields for `CITATION.cff` or repository citation metadata after DOI and authors are confirmed. |
| License decision notes | `manuscript/license_decision_notes.md` | Separates author-generated materials from upstream data products and records license decisions needed before release. |
| Supplementary information draft | `manuscript/supplementary_information_draft.md` | Can be used to prepare supplement or reviewer-response material for methods, source data and interpretation boundaries. |
| Reviewer-response preparation | `manuscript/review_response_preparation.md` | Provides prepared responses to likely questions about data authenticity, product definitions, ocean connectivity and interpretation limits. |

## Minimum acceptance rule

The package should not be sent to collaborators, reviewers or a repository unless `python scripts\finalize_cee_publication_package.py` exits with code 0 and `scripts/audit_publication_readiness.py` reports `PUBLICATION READINESS AUDIT: PASS`.
## Archive verification sidecar

`final_archive_manifest.json` is a required sidecar for `publication_package.zip`. It should be retained with the final archive during internal handoff, repository deposit, and journal submission preparation because it records the ZIP archive's size, SHA256 hash, and final validation evidence.
## Figure evidence logs

Include `logs\manuscript_figure_inventory.md` and `logs\manuscript_figure_inventory.json` with the final evidence bundle. These files identify every manuscript image reference or embedded image and record byte size, dimensions, SHA256, and any read/decode error.
## Final QC acceptance files

Include `manuscript\final_qc_acceptance.json`, `manuscript\final_qc_acceptance.md`, `logs\final_qc_acceptance_audit.txt`, and `logs\final_qc_acceptance_audit.json` with the final evidence bundle. These files document any accepted non-blocking audit notes and confirm that errors or warnings were not waived.
## Archive handoff evidence

Include `logs\archive_handoff_audit.txt`, `logs\archive_handoff_audit.json`, `final_archive_manifest.json`, `publication_package.zip`, and `publication_gate_evidence\` in the final handoff. The handoff audit confirms that archive sidecars remain outside the ZIP and that the ZIP contains the manuscript files.
## Repository deposit evidence

Include `logs\repository_deposit_readiness_audit.txt` and `logs\repository_deposit_readiness_audit.json` with the final evidence bundle. These files document whether the data/code availability text, repository checklist, citation metadata, license decision, software environment, and figure source-data dictionary are ready for journal and repository deposit.
## Final evidence index

Include `logs\final_evidence_index.md` and `logs\final_evidence_index.json` with the final evidence bundle. These files provide the compact inventory of all required evidence artifacts and their pass/fail state.
## Journal submission metadata evidence

Include `logs\journal_submission_metadata_audit.txt` and `logs\journal_submission_metadata_audit.json` with the final evidence bundle. These files document whether title/declarations, submission metadata, target-journal checklist, cover letter, editorial significance statement, author confirmation, AI-use statement, data/code availability text, and reporting-summary preparation are ready for submission.
## Reference metadata evidence

Include `logs\reference_metadata_audit.txt`, `logs\reference_metadata_audit.json`, and `manuscript\reference_verification.md` with the final evidence bundle. These files document reference-section completeness, DOI checks, duplicate DOI checks, and reference verification status.
## Evidence manifest hash sidecar

Include `publication_gate_evidence\evidence_manifest.json` and `publication_gate_evidence\evidence_manifest.sha256` with the final evidence bundle. The SHA256 sidecar verifies the evidence manifest without requiring the manifest to contain a self-referential hash.

The SHA256 sidecar must use the standard two-field form `<sha256>  evidence_manifest.json`; the archive handoff audit verifies both the digest format and the target filename.
## Runtime dependency evidence

Include `logs\python_runtime_dependencies_audit.txt` and `logs\python_runtime_dependencies_audit.json` with the final evidence bundle. These files document whether the active Python environment contains the external modules required by the project scripts.
## Runtime requirements file

Include `requirements-publication.txt` with the final evidence bundle. This file is the external Python package list for rerunning finalization and audit checks.
## Environment diagnostics evidence

Include `logs\publication_environment_diagnostics.txt` with the final evidence bundle. This log records the working directory, Python discovery, Python version, pip version, and presence of key gate/manuscript files at the start of the gate run.
## Manual figure review evidence

Include `logs\manual_figure_review_sheet.md` and `logs\manual_figure_review_sheet.json` with the final evidence bundle. These files provide the human-facing review sheet for manuscript figure inspection.
